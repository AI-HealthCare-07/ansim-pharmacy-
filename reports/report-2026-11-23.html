08운영 규칙과 위험 대응

1인 수행 조건

  1. OCR·LLM을 직접 학습하지 않고 제공 API를 씁니다.
  2. 처방 약은 DB 정확 조회, 임베딩은 생활 수칙 문서만 합니다.
  3. 12/4 초기 모델은 고정 사용자 데모 기준입니다.
  4. 12/11 기능 동결, 이후는 배포·시험·발표만 합니다.
  5. 선택 기능은 필수 완료 후 1~2개만 합니다.
  6. 막히면 3시간 안에 임시 응답(가짜 JSON)으로 다음 단계를 잇습니다.

11이슈 · 리스크

정리됨DOC-007은 1차 필수로 확정했습니다. 본인·가족 처방전과 진료기록(비식별본)을 쓰는 경로로 11/26에 구현합니다. 12/18에는 여유 시 TTS(MED-013, 선택)만 남깁니다. 요구사항은 필수 35 / 선택 7입니다. 원본 엑셀(구현 단계 칸, ID 체계 시트, 12/18 행)과 Word 일정표는 아직 고치지 않았습니다.
일정11/23 하루에 적재 작업이 몰려 있습니다. 허가정보 전량 + e약은요 + 심평원 EDI 연결표 + 기준일 기록, 그리고 가족 PDF 비식별 시험이 겹칩니다. 공공 API 하루 호출 한도에 걸리면 11/24로 넘어갈 수 있습니다.
상태계획서 상태가 전부 “미착수”입니다. 저장소에는 11/20~23 작업이 진행돼 있으니 상태 칸과 진행률(현재 0.0)을 갱신해야 멘토 보고와 맞습니다.
확인업로드 한도가 요구사항은 20MB, API 명세서는 10MB입니다 (DOC-001 비고). 계획의 테이블 이름은 drugs, 코드는 medicines입니다.
보안docker-compose에 DB 기본 비밀번호가 들어 있습니다. 로컬 개발용으로는 괜찮지만 12/15 EC2 배포 전에 환경 변수로 바꿔야 합니다.
